# 中考阅读理解题目生成

## 核心原则

题目质量优先，证据可追溯。每道题必须有明确的文内证据、唯一的正确答案和清晰的推理路径。难度来自信息关系和思维任务，不来自生僻词汇。

本 Skill 负责根据已完成的文章生成阅读理解选择题。如需先进行文章写作，请使用 `zhongkao-article-writer` Skill。

## 开始前必须读取

每次任务先读取：

1. `references/approved-standards.md`：题目默认配置、选项规范、答案分布规则。
2. `references/output-contract.md`：固定交付结构。
3. `references/question-design.md`：完整题型规范、命题模板和干扰项设计方法。
4. `references/explanation-writing.md`：答案解析撰写方法（真题对齐的「导语 + 逐题详解」结构）。

出题前**必须调用** `mcp__zhongkao-mcp__draw_blueprint` 随机抽取题目蓝图，确保题型覆盖不重复；未抽取蓝图不得进入逐题编写。

开始新任务时，先用 `mcp__zhongkao-mcp__workflow_init(level="...")`（或 `workflow_reset`）清空上一个任务的记录，避免旧状态干扰本次导出门禁；可随时用 `mcp__zhongkao-mcp__workflow_status` 查看各硬性步骤完成情况（工具会自动把 `draw_blueprint` / `validate_questions` / `check_passage` 的结果记录到工作流状态，无需手动登记）。

## 输入

接受写作完成后的英文文章，并识别：

- 正文（含标题）
- `level: standard | extended`
- `question_count`，默认 5
- `option_count`，默认 4，可设 3
- 文章的指标报告（如有，便于了解可考点和超纲词）

🔴 CHECKPOINT：会话中未指定档位时，**先询问用户选择档位**（`standard | extended`），不得静默默认（遵循项目 CLAUDE.md 第 5 节）。本工具只面向九年级，年级固定为 9，不提供其他年级选项。

🔴 STOP：正文缺失时**停止**，说明原因，等用户补齐正文后再继续。

## 工作流

### 1. 阅读并分析文章

通读正文，提取：

- **篇章结构**：段落功能（引入/展开/例证/转折/结论）、段落间逻辑关系
- **可考点清单**：每段的 facts / causes / contrasts / attitudes / references / keywords
- **证据分布**：标注可出题的句子位置和跨段关系

可考点必须满足：
- 原文有明确依据，不依赖猜测
- 信息完整，不因改写而丢失关键限定
- 难度来自理解加工，不来自生词或复杂句法

### 2. 确定题目配置

根据档位决定：

| 参数 | 标准档 | 拓展档 |
|------|--------|--------|
| 默认题数 | 5 | 5 |
| 默认选项数 | 4 | 4 |
| 推理跨度 | 同段或相邻句为主 | 至少一道跨段或论证作用题 |
| 题型覆盖 | 写作手法 1 + 词义/细节 1 + 推理 1 + 排序或推断 1 + 主旨 1 | 同上，推理或主旨优先跨段/论证作用 |

### 3. 抽取题目蓝图（必须执行）

🔴 CHECKPOINT：**硬性步骤**——必须调用 `mcp__zhongkao-mcp__draw_blueprint` 随机抽取五题蓝图；此步不可跳过，未抽取蓝图不得进入第 4 步逐题编写。

使用 `mcp__zhongkao-mcp__draw_blueprint` 随机抽取五题蓝图：

```
mcp__zhongkao-mcp__draw_blueprint()   # 文章无标题（或已有标题但调用方忽略该规则）
mcp__zhongkao-mcp__draw_blueprint(article_has_title=true)   # 文章已有标题：Q5 自动改出推断题，不出 best title
```

返回结果包含五个位置（写作手法/细节、词义或细节、推理判断、排序或推断、主旨）各一道子题型及其模板和约束。题位固定为：Q1 写作手法(30%) 或 细节理解(70%)，Q2 词义猜测(70%) 或 细节理解(30%)，Q3 推理判断（含段落主旨；推理池内段落主旨 I-08 权重 5%，其余 6 类均分 95%），Q4 排序(80%) 或 推断(20%，复用 Q3 推理池，推断:排序 = 1:4)，Q5 主旨大意。

**三条硬性标注/选型规则（出题时必须遵守）：**
- **段落主旨题标 MAIN IDEA**：Q3 若出段落主旨题（`What is paragraph X mainly about?`），`type` 必须用 `main_idea`（导出标签 MAIN IDEA，对应 M-03 段落大意），不得用 `inference`（否则标签显示 INFERENCE）。蓝图抽取到 `I-08` 时已自动转 `main_idea`/`M-03`。
- **文章已有标题时 Q5 不出最佳标题**：文章自带标题时，Q5 不得出「最佳标题」（M-01）题型，改为推断题（I 类）。调用 `draw_blueprint` 时传 `article_has_title=true` 即可自动规避；手动编写蓝图时同样遵守。
- **写作手法题标签用 CRAFT**：写作手法题（`type=writing_technique`）导出时的题型标签为 **CRAFT**（不再用 WRITING TECHNIQUE）。题型标签统一右对齐、灰色（导出器 `run_export_docx` 已默认实现）。

`draw_blueprint` 会自动记录「蓝图已抽取」及蓝图 codes 到工作流状态；**`export_docx` 在未抽蓝图时会直接拦截导出**，这是门禁兜底，不代表可以跳过本步——仍须按蓝图逐题编写。

#### 段落落点规划（证据随行文顺序严格执行）

蓝图确定题型后，先标注每题对应的证据段落，再进入逐题编写。**证据段落必须严格按文章行文顺序依次分布，五题证据段落序号必须单调递增：Q1 < Q2 < Q3 < Q4 < Q5，不得回退、不得乱序。**

| 题位 | 题型 | 段落落点（严格递增） |
|------|------|---------|
| Q1 | 写作手法(30%) 或 细节理解(70%) | 固定第 1 段 |
| Q2 | 词义猜测(70%) 或 细节理解(30%) | 第 2 段（文章多于 5 段时取靠前段落，仍须 > Q1） |
| Q3 | 推理判断（含段落主旨；段落主旨题标 **MAIN IDEA**，`type=main_idea`） | 第 3 段（多于 5 段时取中间段落，仍须 > Q2） |
| Q4 | 排序(80%) 或 推断(20%) | 排序→全文（跨段时间线）；推断→第 4 段或靠后段落（须 > Q3） |
| Q5 | 主旨大意（文章已有标题时改出推断题 I 类，不出 best title） | 末段或全文（全文题不绑单段；单段题须 > Q4） |

段数与题目数对应（严格递增，可跳段、不可回退）：

- **文章正好 5 段**：Q1→第 1 段，Q2→第 2 段，Q3→第 3 段，Q4→第 4 段；第 5 段服务于 Q4（排序→事件素材 / 推断→跨段素材）和 Q5 主旨的全文覆盖。
- **文章多于 5 段**（如 7 段）：按 1→2→3→4→末段依次取（如 Q1→1、Q2→2、Q3→3、Q4→4、Q5→7），确保证据段落单调递增；跳过的段落只允许出现在 Q4/Q5 之后。
- **文章少于 5 段**（如 4 段）：Q2 取第 2 段、Q3 取第 3 段、Q4 取第 4 段，允许就近跨段，整体严格从前往后。

若自动抽取的题型与文章特征不匹配（如文章没有可考的写作手法却抽到了 WT 类、或没有清晰的排序时间标记却抽到了 O 类），可手动调整并说明理由。

### 4. 逐题编写

**题干与解析按真题撰写方式（对应题型映射，见 `question-design.md`「题干模板库与解析方法」与 `explanation-writing.md`）：**

- **题干**：抽中某类题型（WT/D/V/I/O/M）后，题干整句复用该题型对应的**题干模板**（填变量：划线词/名词），不得自由改写。
- **解析**：每题解析按该题型的**解析方法**撰写（引证两段式：定位短语 + 逐字引原文 + 一句话下结论），详见 `explanation-writing.md`。

每题按以下顺序生成：

1. **写能力指标**：学生需要展示什么阅读理解能力。
2. **标证据段落**：先按上一步"段落落点规划"确认该题对应哪个段落，再在段落内精确定位支持正确答案的句子，标注证据跨度（同句/同段跨句/跨段）。全文题（排序、主旨）例外，不绑单段。
3. **写推理链**：从证据到正确答案的 1—3 步推理过程。
4. **写正确项**：对原文进行自然同义转述，不照抄原句。
5. **设计干扰项**：从 8 种允许的干扰机制中选择，确保与正确项同词性、同句式、相近长度和同抽象层级。
6. **逐项写错误点**：每个干扰项必须标注具体的错因类型。
7. **反向检查**：确认不存在第二个可答项。

#### 猜词题取材规则（V 类）

- **目标词必须为单个单词（不得选短语/词组）**，优先选**长难词**；短语（如 `give up`、`a good deal of` 之类）不可作猜词考点。
- **允许选文中已加中文注释的词**：把该词的注释从正文去掉即可作考点（去掉注释后该词不再"给答案"）；去注释的操作不参与生词覆盖率计算。
- **选词必须通读上下文**：目标词必须能靠**语境线索**（定义/对比/因果/身份提示等）推断出词义；**不得**选靠构词法直接拼出、或纯并列列举中的专业名词（如 `cybersecurity` = cyber+security，属"为出题而出题"）。要通读上下文，挑选真正需要推敲语义的词。
- **猜词题题干格式**：统一句式 `What does the underlined word "X" (probably) mean?`，题干不写段落编号（仅首末段可用 `the first paragraph` / `the last paragraph`）；目标词在正文加单下划线即定位；不得以 `...` 结尾；validator 有咨询性检查。
- **正文目标词加下划线**：猜词题的目标词，须在导出文档正文对应位置加**单下划线**标注，与题干中的词呼应。**划线词必须与原文词形逐字一致**：下划线须覆盖原文实际出现的完整单词（如原文 `anchoring` 就划 `anchoring`），不得只截取单词的一部分（如划 `anchoring` 的前半截 `anchor`），也不得将派生词换成原形词；若原文该词位于句首（如 `Primary`），按原文大小写划线即可。**加下划线不得破坏单词间距**：目标词通常需拆成独立 run 并设下划线，此时须保证其与前后单词之间仍有空格分隔，不得粘连（如 `texturewas` 应为 `texture was`）。若目标词原本带中文注释且已去掉注释，尤其注意注释两侧的空格归属——删注释后仍须保留单词间空格。

#### 推断题范围规则（I-01 隐含信息）

- `What can we infer / learn from the passage?` 类题干默认**针对全文**，不写段落编号（行文顺序由题序暗含，证据段落见「段落落点规划」）。
- 仅首末段推断可在题干写 `the last paragraph` / `the first paragraph`（如 `What is implied in the last paragraph?`）；中间段落不点明。

#### 干扰项允许的错误机制（8 种）

| 错因 | 定义 | 适用占比 |
|------|------|---------|
| 对象错配 | 信息匹配错误对象（张冠李戴） | 30% – 40% |
| 条件或限定缺失 | 省略了原文中的时间/地点/程度等限定条件 | 10% – 20% |
| 范围扩大或缩小 | 将部分说成全部、将全部说成部分 | 15% – 25% |
| 因果方向倒置 | 将原因说成结果、结果说成原因 | 5% – 15% |
| 时间顺序颠倒 | 事件发生先后顺序颠倒 | 5% – 10% |
| 局部真实但答非所问 | 选项内容在文中真实存在，但不回应题干问题 | 10% – 20% |
| 主题相关但不是本文重点 | 选项与文章主题一致，但非该题对应段落的核心信息 | 5% – 15% |
| 确定性膨胀 | 把可能写成确定、把一项研究写成多项共识 | 5% – 10% |

**各题型首选错因映射**（每题优先从对应组选干扰项，减少盲目组合）：

| 题型 | 首选错因 | 次选 |
|------|---------|------|
| 细节理解 | 对象错配 / 范围扩大缩小 | 条件限定缺失 |
| 词义猜测 | 局部真实但答非所问 | 对象错配 |
| 推理判断 | 过度推断（确定性膨胀 / 范围扩大） | 因果倒置 |
| 排序 | 时间顺序颠倒 | 局部真实但答非所问 |
| 写作手法 / 主旨 | 主题相关但不是重点 / 范围缩小 | 局部真实但答非所问 |

#### 禁止使用的干扰手法

- ❌ 利用 `all / never / only` 等显眼绝对词泄露答案
- ❌ 语法错误（选项存在时态/主谓不一致等）
- ❌ 明显不平行的选项（长度/结构/抽象层级差异过大）
- ❌ 一个异常长或异常具体的正确项（泄露答案位置）
- ❌ 依赖文外常识争议（学生需课外知识才能排除）
- ❌ 与主题完全无关的荒谬项（学生无需读文即可排除）
- ❌ 部分正确的模糊地带（干扰项与正确项有重叠，造成双答案风险）
- ❌ **与全文主旨/核心事实方向性矛盾的干扰项**——方向相反即"一眼假"，学生凭主旨即可排除
- ❌ **常识性荒谬项**——学生不读文靠常识就能排除的选项，干扰性为零
- ❌ **语义场跑偏**：干扰项与题干考点不同域——应留在考点语义场内，从时间/程度/对象/前提等维度做文章

### 5. 题组整体检查

逐题完成后，进行题组级别检查：

- [ ] 无前后题暗示（前题信息不能泄露后题答案）
- [ ] 难度排列递增（易→中→难）
- [ ] 选项分布均衡（A/B/C/D 频次差 ≤ 2）
- [ ] 五个题位各出一道（Q1 写作手法或细节、Q2 词义或细节、Q3 推理、Q4 排序或推断、Q5 主旨）；Q1 抽中细节时允许与 Q2 细节并存，但证据句不得重复使用
- [ ] 证据段落严格递增（Q1→第 1 段、Q2→第 2 段、Q3→第 3 段、Q4→第 4 段或靠后、Q5→末段或全文；Q4 排序→全文），五题序号单调递增 Q1<Q2<Q3<Q4<Q5，无回退、无乱序
- [ ] 题干定位明确（段落指向清晰，不使用过度宽泛的 "According to the passage" 除非是全文主旨题）
- [ ] 选项词汇 100% 课标词

### 6. 自动化校验（硬性步骤）

🔴 CHECKPOINT：**硬性门槛**——必须调用 `mcp__zhongkao-mcp__validate_questions` 校验；`all_pass` 为 true 前不得进入第 7 步双向追溯，更不得导出 Word。

使用 `mcp__zhongkao-mcp__validate_questions` 自动校验题目质量：

```
mcp__zhongkao-mcp__validate_questions(
    questions=[{"id": 1, "stem": "...", "options": [...], "answer": "D", "type": "detail"}, ...],
    option_count=4
)
```

自动检查项：
| 检查项 | 标准 | 自动判定 |
|--------|------|---------|
| 选项格式 | 正确选项数量、连续字母、前缀格式（A. / B. / C. / D.） | 通过/不通过 |
| 答案唯一性 | 答案在有效选项字母范围内 | 通过/不通过 |
| 题型覆盖 | 每篇必须覆盖 vocabulary_or_detail / inference / main_idea，外加 writing_technique 或 detail（Q1 二选一）、ordering 或 inference（Q4 二选一） | 通过/不通过 |
| 选项长度均衡 | 最长选项 ≤ 最短 × 2（词数）且 ≤ 30 字符差。validator 用双条件（超 2 倍 **且** 差 >30 字符）判定，排序题的序列选项（如 `②③①④`）长度天然接近，实际很少触发；若触发需按通用标准调整。序列选项只需保证所有选项同为完整序列（无缺标号/错序） | 通过/不通过 |
| 绝对词泄露 | `all / never / always / only / none / every / no one` 出现在干扰项中 | 标记预警 |

如有 `fail` 或 `review_required` 项，修正后重新校验，直至 `all_pass` 为 true。

`validate_questions` 会自动记录校验结果到工作流状态；**`export_docx` 在 `all_pass` 不为 true 时会拦截导出**，这是门禁兜底，不代表可以跳过本步——仍须校验至 all_pass 后再导出。

若 `mcp__zhongkao-mcp__*` 工具在当前会话不可用（未加载或 server 未上线），可直接调用源码模块绕过 MCP：

```
python -c "from src.validator import run_validate_questions; ..."
python -c "from src.exporter import run_export_docx; ..."
```

路径为 `Part1-文章改写\zhongkao-mcp\src\`（源码函数：`run_draw_blueprint` / `run_validate_questions` / `run_export_docx`）。调用前先确认根 `.mcp.json` 路径仍指向真实代码；路径正确后重启会话通常即可恢复 MCP。

#### 仅校验已有题目（不重出题、不导出）

用户只要求**校验一组已有题目**（双答案/文外常识/格式问题）时，不阅读分析文章、不抽蓝图、不出题、不导出，直接执行轻量流程：

1. 读取题目列表，确认 `stem / options / answer / type` 字段齐全
2. 调用 `mcp__zhongkao-mcp__validate_questions`（`option_count` 按实际选项数传，3 选项传 3）
3. 逐题人工核查：证据句能否精确定位、是否存在第二个可答项、干扰项是否依赖文外常识
4. **态度题锚点核查**：题干含 `the writer` 时，答案引证必须落在**作者本人表述**（叙事/评论/总结句）上；被引述者（专家/教授/受访者）的观点不得作为作者态度题依据——**作者客观报道 ≠ 作者认同**；若考点在被引述者，题干必须点名引述者（`According to X` / `X thinks...`），或改用其他锚点
5. 输出校验结论：`all_pass` 状态、问题清单及对应修正建议；不生成题目 Word，不抽蓝图

仅校验模式不出题、不导出；是否需要导出由用户另行提出。

### 7. 双向追溯终检

- 从题目回原文：每个正确项的证据句是否能精确定位且唯一支持该答案
- 从原文到题目：是否漏掉重要可考点

任何无法回挂的内容：

- 若正确项无明确文内证据，修改或删除
- 若干扰项使用了文外常识或荒谬项，替换为基于文内信息的合理干扰

### 8. 生成题目 Word 文档

🔴 CHECKPOINT：**输出目录（硬性步骤）——导出前必须确认输出路径。** 若用户会话中**未明确指定**题目 Word 的保存目录，**必须先询问用户**「题目 Word 保存到哪个目录？」，待用户给出路径后再导出；不得静默默认任何默认目录。用户指定的路径优先。该目录应与 Part1 报告 Word 的目录分别确认。

推荐使用 `mcp__zhongkao-mcp__export_docx` 工具一键导出（自动处理样式和排版）：

```
mcp__zhongkao-mcp__export_docx(
    title="文章标题",
    body="正文（段落用 \\n\\n 分隔）",
    questions=[{"stem": "...", "options": ["A. ...", "B. ...", "C. ...", "D. ..."], "answer": "D", "type": "writing_technique"}, ...],
    answer_key=["D", "A", "B", "C", "B"],
    explanations=["本文是一篇说明文，……（导语：全文总结，导出器自动独立成段、不加编号、后接空行）", "第X段……可知……（逐题详解：每题一条，不带编号，导出器从1开始）", "……", "……", "……", "……"],
    output_path="输出路径.docx"
)
```

`option_count` 只影响选项数量，导出参数不变：3 选项题组时 `options` 每项恰好 A—C（3 个），`answer_key` 对应 3 个字母，`explanations` 第 1 条为导语、其余与题目一一对应。

**导出拦截（门禁兜底）**：`export_docx` 在缺前置硬性步骤时会拒绝导出并返回缺步清单——典型触发原因：未调用 `draw_blueprint`、`validate_questions` 未到 all_pass、或正文无中文注释（但 `check_passage` 检出超纲词）。被拦截时按提示补做对应步骤（重跑 `draw_blueprint` / `validate_questions`、换带注释正文），**不要绕过拦截强行导出**；可用 `workflow_status` 查看还缺哪几步。

**简版交付**：用户明确要求简版时，跳过 Word 导出，仅在聊天展示题目蓝图和选择题全文。

文档内容：
- 标题："Reading Comprehension"
- 说明："Read the passage and choose the best answer for each question."
- 英文正文（每段首行缩进）
- 选择题（题干加粗，选项缩进）
- 末尾附 Answer Key（格式：`1. D   2. A   3. B   4. C`）
- Answer Key 之后附**答案解析**：按 `explanation-writing.md` 的「导语 + 逐题详解」结构（导语一组一条；每题详解 = 正确答案 + 原文证据 + 干扰项错误点，中英文均可，引证两段式）

样式要求：Arial 字体 12pt，中文字体设置为微软雅黑，行间距 1.5 倍，标题 20pt 居中，题号使用 "1." "2." 数字标号。

**交付前必须确认：**

1. 题目数量、选项数量和答案与对话中输出的一致。
2. 正文用**带中文注释版**（与 Part1 交付的正文一致，含 `theory（理论）` 等注释）；不得传无注释正文导致注释丢失。Part1 不再单独导出纯文章 Word，题目 Word 即承载正文的唯一导出文档。
3. `stem` 字段**不带数字标号**（导出器自动编号，避免 `1. 1.` 重复）；排序题（Q4）stem 内先用 ①/②/③/④ 列出事件（每事件一行）。
4. 选项字母和标点正确（A. / B. / C. / D.），题干结尾有问号。**排序题（Q4）例外**：stem 以 ①/②/③/④ 事件清单结尾，在清单前用一句问句引出（如 `Which is the correct order of the following events?`），事件清单本身不以问号结尾。validator 对 `type == "ordering"` 的题只检查 ①/② 事件清单是否齐全，不因清单结尾缺问号报错。
5. Word 文档末尾包含 Answer Key 和答案解析（`explanations` 参数：第 1 条为导语、其余与题目一一对应）。**解析文本不带数字标号**（同 stem 约定：导语与每条详解只写内容本身，如 `本文是一篇说明文，……`、`第X段……可知……`，不带 `1.` 前缀；导出器识别导语后独立成段、不加编号、后接空行，逐题详解从 `1.` 开始编号）。

## 交付门槛

以下任一严重项不通过，不得把结果标为"可交付"：

- 题目存在两个可答项或依赖文外常识
- 正确答案没有明确文内证据
- 干扰项使用绝对词（all/never/only 等）泄露答案
- 选项长度严重不均（最长 > 最短 × 2 且差 > 30 字符，双条件；与 validator 一致）
- 五题未覆盖五种能力类型
- 正确答案分布严重倾斜：**4 选项时**同一字母出现 ≥3 次；**3 选项时**按 5 题 3 字母换算，同一字母出现 ≥3 次同样算倾斜（3 选项下 5 题必然有重复，但任一字母达 3 次仍不合格）
- 前后题目信息泄露（前题答案暗示后题答案）
- **正文全文词数 > 350**：Part1 交付的正文须 ≤350 词（Part1 的 `check_passage` 已硬性校验 word_count）；若承接的正文超 350 词，回 Part1 压缩，不得带超限正文出题导出

### 交付前最终自查清单（🔴 CHECKPOINT：逐项勾选，缺一不可，全部确认前不导出）

导出 Word 前，逐项确认以下步骤**全部执行过**；任一未勾选即补做，不得直接交付：

- [ ] **① draw_blueprint 已执行**（第 3 步蓝图已抽取，非跳过）
- [ ] **② 逐题编写已按蓝图完成**（Q1 写作手法或细节、Q2 词义或细节、Q3 推理、Q4 排序或推断、Q5 主旨；题干按题型套用真题固定句式、解析按「引证两段式」撰写）
- [ ] **③ 题组整体检查已过**（无前后暗示、难度递增、选项分布均衡、证据段分布正确、选项词汇课标词）
- [ ] **④ validate_questions 已执行且 all_pass 为 true**（第 6 步硬性门槛）
- [ ] **⑤ 双向追溯已终检**（正确项证据可精确定位、无第二个可答项）
- [ ] **⑥ 输出目录已确认**（用户已指定，或已询问并确认采用默认目录）
- [ ] **⑦ 题目 Word 已导出**（含正文带注释版 + Answer Key + 每题答案解析）

> 说明：仅校验模式（不重出题、不导出）例外，只要求勾选 ④。
>
> 以上自查清单由 MCP 门禁自动兜底：`export_docx` 会拦截缺步导出（未抽蓝图 / 校验未 all_pass / 正文缺中文注释）。若导出被拦截，说明有步骤遗漏，按提示补做后再导出。

## 常见错误（不要这样做）

| 不要做 | 后果 | 应该 |
|---|---|---|
| 题目都能单句定位 | 考查退化为机械定位，达不到中考"信息整合/关系推断"的能力要求 | 用蓝图保证信息整合、关系推断和全篇理解 |
| 证据段落在文章前后乱序或扎堆（如 Q3 用首段、Q2 用末段） | 违反「五题证据段落严格递增」要求，第 5 步题组整体检查不通过，须返工重排 | 按段落落点规划：Q1→第 1 段、Q2→第 2 段、Q3→第 3 段、Q4→第 4 段或靠后、Q5→末段或全文，严格递增 Q1<Q2<Q3<Q4<Q5，不得回退、不得乱序 |
| 只报答案不报证据 | 违背 output-contract，答案解析缺失，用户无法复核 | 按输出合同给证据、推理和干扰项错误点 |
| 正确项照抄原文 | 原文照抄等于把答案送上门，考查失真 | 进行自然同义转述 |
| 干扰项完全不相关 | 学生无需读文即可排除，干扰项形同虚设 | 基于文内信息设计合理干扰 |
| 选项长度泄露答案 | 异常长/短的选项暴露正确项，违反交付门槛「选项长度均衡」 | 确保四个选项长度均衡 |
| 题干比正文还难 | 题干生词反成额外门槛，考查错位 | 题干语言应低于正文一个难度级别 |
| 四道题都是细节定位 | 题型覆盖不达标（缺推理/主旨），违反交付门槛「覆盖五种能力」 | 用蓝图保证至少覆盖五种能力 |
| 题干自由造句、不用固定句式 | 按 `question-design.md`「题干模板库」整句复用：猜词统一 `What does the underlined word "X" mean?`、指代统一 `refer to`、标题/主旨/出处/写作手法各用固定套语 | 题干整句复用真题固定句式，不自由改写 |
| 题干写编号段落 | 题干不写 `paragraph 2` 等编号段落（行文顺序由题序暗含）；仅首末段可用 `the first paragraph` / `the last paragraph` | 题干不写编号段落，段位定位只用于解析引证 |
| 段落主旨与全文主旨句式混用 | 段（仅首末段）：`What is the last/first paragraph mainly about?`；全文：`What is the main idea of the passage?`；句式必须区分 | 段与全文用各自固定句式 |
| 解析无证据引文、空泛断言 | 按 `explanation-writing.md` 引证两段式：定位短语 + 逐字引原文 + 结论动词（说明/可知/因此/推知/最可能出自） | 每题详解 = 定位短语 + 逐字引原文 + 一句话下结论 |
| 解析逐项排除所有干扰项、篇幅冗长 | 干扰项"少而准"：多数只讲正确项（引证即间接排除），易混题才显式点出可验证否定（文中无提及/非主旨/只有前者/只有后者） | 干扰项按"少而准"处理 |

## 失败模式与 Fallback

| # | 触发信号 | 第一选择 | 备用 |
|---|---------|---------|------|
| 1 | `mcp__zhongkao-mcp__*` 会话中不可用 | 先查工具包根 `.mcp.json` 路径是否指向真实代码；路径正确则重启会话加载 | python 直调 `Part1-文章改写/zhongkao-mcp/src/` 的 `run_draw_blueprint` / `run_validate_questions` / `run_export_docx` 绕过 MCP |
| 2 | 蓝图自动抽到的题型与文章特征不符（无写作手法却抽 WT、无清晰时间标记却抽 O 类） | 手动调整题型并说明理由（见第 3 步段落落点规划） | 重跑 `draw_blueprint` 重新抽取 |
| 3 | `validate_questions` 返回 fail / review_required | 按检查项逐条修正后重跑，直到 all_pass 为 true | 用 `workflow_status` 定位具体未过的步骤 |
| 4 | `export_docx` 拦截导出（未抽蓝图 / 校验未 all_pass / 正文缺中文注释） | 按缺步清单补做对应步骤，不绕过拦截 | 查 `workflow_status` 确认还缺哪一步 |
| 5 | 仅校验模式误入完整流程（重出题/导出） | 回到第 6 步「仅校验已有题目」轻量流程，只输出校验结论 | 需要导出时由用户另行提出 |
| 6 | 承接的 Part1 正文 > 350 词，或 Part1 未交付 / 未 all_pass | 回 Part1 压缩或补齐后再出题 | 用「执行前核对」清单逐项确认交接完整 |
