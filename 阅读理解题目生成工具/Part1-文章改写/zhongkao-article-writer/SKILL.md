# 中考阅读文章写作

## 核心原则

从原文提取客观事实 → 匹配行文逻辑模块套用骨架 → 撰写原创文章。文章可读、可考、可追溯。难度来自信息关系和思维任务，不来自生僻词堆积；不改变事实、证据类型、逻辑方向或文化身份。

本 Skill 负责文章写作。如需生成阅读理解选择题，请使用 `zhongkao-question-generator` Skill。

## 开始前必须读取

每次任务先读取：

1. 项目 `CLAUDE.md`（`../../CLAUDE.md`，即本 Skill 所在包根目录的 `CLAUDE.md`）：报告结构（含文章全文段内标注）、静默输出、中文注释最后一步、MCP 配置位置等全局约定
2. `references/approved-standards.md`：两档参数和专名规则
3. `references/output-contract.md`：固定交付结构

按任务读取：

- 匹配行文逻辑、套用篇章骨架时，读本工具包根目录 `reading-explorer-writing` Skill 的两个 reference：
  - `../../reading-explorer-writing/references/module-library.md`（8 大模块 + 组合原则 + Level 2 变体）
  - `../../reading-explorer-writing/references/mental-models-heuristics.md`（15 共识模型 + 20 决策启发式 + 20 反模式）
- 词汇降级与句法处理（第 5 步撰写、第 6 步地道性审校）时，读 `references/adaptation-methods.md`（词汇/句法/语篇降级方法 + 地道性门槛 + Humanizer 清单）
- 材料准入与内容审校（第 1 步准入、第 7 步指标）时，读 `references/curriculum-constraints.md`（课标约束矩阵 + 内容审校依据）

不要把 1601 条词表全部载入上下文。词汇检查优先使用 `mcp__vocab-checker__check_text` 和 `mcp__vocab-checker__check_grade_level`（基于 spaCy 词形还原 + 派生词缀匹配，覆盖率更准确）。

**开始新任务时**，先用 `mcp__zhongkao-mcp__workflow_init(level="...")`（或 `workflow_reset`）清空上一个任务的记录，避免旧状态干扰本次交付（工作流状态写入 `.zhongkao_workflow.json`，供 Part2 的导出门禁使用）；可随时用 `mcp__zhongkao-mcp__workflow_status` 查看各硬性步骤完成情况。`check_passage` 会自动记录指标结果，无需手动登记。

**外部引用缺失时的退化**：上述 `reading-explorer-writing` 的两个 reference（`module-library.md`、`mental-models-heuristics.md`）位于本工具包根目录的 `reading-explorer-writing/` 目录，若读取时发现路径不存在或不可读，**不要停止**，按以下规则降级：第 3 步退化为兜底模式（总分总 / 起承转合）完成篇章结构；第 5 步跳过外部模块骨架、直接按兜底结构撰写；第 6 步跳过 A1–A20 反模式清单，改用本包 `references/adaptation-methods.md` 的 Humanizer 清单；在报告"写作说明"一节注明"外部模块库不可用，已用兜底结构"。本 skill 包内 `references/` 下四个文件（`approved-standards.md`、`output-contract.md`、`adaptation-methods.md`、`curriculum-constraints.md`）是必需的，缺任一则先检查路径再继续。

## 输入

接受正文、网页内容或本地文档，并识别：

- 原文标题、来源、日期、链接（如有）
- `level: standard | extended`
- 目标主题或课程单元（可选）
- 必须保留的事实、教学词汇或专名（可选）

🔴 CHECKPOINT：会话中未指定档位时，**先询问用户选择档位**（`standard | extended`），不得静默默认（遵循项目 CLAUDE.md 第 5 节）。本工具只面向九年级，年级固定为 9，不提供其他年级选项。

🔴 STOP：正文缺失、事实片段不足以形成完整语篇、材料明显不适合初中生时**停止**，说明原因和所需补充，等用户决定换材/补材后再继续。不要因缺少来源链接而停止；把"来源信息未提供"记入元数据。

## 工作流

### 1. 材料准入

判断主题范畴、语篇类型、年龄适切性、价值导向和事实充分度。

拒绝或建议换材的情形：

- 核心内容依赖成人经验、暴力猎奇或不宜呈现的细节
- 删除敏感内容后主线无法成立
- 原文只有零散结论，没有支持过程或上下文
- 需要大量新增背景才能读懂
- 科学、文化或社会议题无法在不失真的前提下降到目标档

### 2. 提取客观事实

从原文中提取所有客观事实，输出为编号列表。每条必须：

- **纯信息点**：只包含"是什么"，不包含原文的比喻、修饰、评价性语言
- **不含修辞**
- **不含独特表达**
- **不遗漏**：人物、时间、地点、数据、过程、结果、因果、引述观点全部提取

提取完成后建立四类账本：

| 类型 | 记录内容 |
|---|---|
| 事实 | 人物、时间、地点、行为、数据、过程、结果 |
| 研究结果 | 研究数量、对象、方法、发现、限制 |
| 专家观点 | 发言者、身份、观点、是否逐字引语 |
| 作者判断 | 评价、推测、主张、语气强度 |

为每项标注：`必须保留 / 可压缩 / 可删除`。先做账本，再写正文。

同时输出一句**中心思想**。

### 3. 诊断素材，匹配行文逻辑模块

按 reading-explorer-writing 的诊断表自上而下匹配（命中即停）：

| 序 | 源素材特征 | 命中模块 |
|---|---|---|
| 1 | 采访/问答稿有受访者 | 七·访谈问答型 |
| 2 | N 个并列条目（建议/榜单/活动） | 五·总分列举清单型 |
| 3 | 两派对立观点/两个镜像样本可对摆 | 四·正反对照论证型（含辩论体/纠偏式变体） |
| 4 | 完整故事弧线（人物/事件/时间线） | 六·叙事传记型（含第一人称特写变体） |
| 5 | 未解之谜/悬案可摆正反证据 | 三·解谜推理型（含证据升级变体） |
| 6 | 有"疼/具体"的场景可开场 | 八·场景开篇问题放大型 |
| 7 | 可拆"现象→机制→成因"三层递进 | 二·现象—机制—成因型 |
| 8 | 以上皆无 → 提炼核心问题 + 2-4 个并列答案 | 一·悬问驱动型 |

同时按组合原则决定辅助模块：开场用场景(八)或设问(一)，中段用并列/递进/对仗/天平/问答/时间线，结尾用预测/引语/画面。

多模块冲突裁决：选"最能放大素材亮点"的作主模块，其余作辅助。明确说出选择理由。

**兜底模式（素材无明显模块特征时）：**

| 模式 | 段落数 | 结构说明 |
|------|--------|---------|
| 总分总 | 3 – 5 段 | 首段引入主题/事件 → 中间段展开细节/论证 → 末段总结/展望 |
| 起承转合 | 4 段 | 起（事件引入）→ 承（扩散/展开）→ 转（转折/应对/问题）→ 合（收束/结论/展望） |

### 4. 决定专名与引述

**专名默认保留，不做泛化。** 原文中的人名、机构名、地名、作品名、法案名、品牌名等专有名词，一律保留原样。删除专名的情形仅限：

- 该专名在原文中仅出现一次且不承担任何信息功能（纯装饰性提及）
- 删除后不影响任何事实链条、因果逻辑或观点归属

不对专名设置数量限制。保留 5 个、8 个甚至更多专名均可，只要每个都承担信息功能。专名处理是写作阶段决策，报告 Word 不单列"专名与引述处理"一节。

引述转换必须保持证据类型和数量：

- 一名专家：`An expert says`，不能写 `Experts say`
- 多名专家且观点确可合并：`Experts say`
- 单项研究：`A study shows/found`
- 多项独立研究：`Studies show`
- 研究团队：`Researchers found`

不得凭空增加专家、研究或共识。非逐字改写的引语改为间接引语。

### 5. 搭骨架并撰写原创文章

打开 `module-library.md` 对应模块，套用结构骨架：

- **搭骨架**：逐段标功能（导语钩子/分论点/证据/收尾），每段一个"意图"
- **撰写**：每段按"意图"填充素材；强制跑共识模型（设问承诺要兑现、细节要可成像、数据要挂场景、引语要分工、结尾要升级不总结）
- **标题**：重新拟定
- **段落**：4–5 段，每段有唯一功能，每段不超过 90 词，全文不超过 350 词（中考短文不用 Level 2 小节标题分区）
- **语言**：所有句子原创撰写，不照搬原文句式。**不可引用任何原文原句**（硬性规则；导出前由第 7 步的原文原句检测 hook 复核，任何命中即改写重写）
- **专名**：全部保留，不做泛化
- **引述**：保持发言人身份和观点不变
- **不新增事实**
- **全程过反模式清单**（mental-models-heuristics.md，A1–A20）：不堆数据开场、承诺要兑现、结尾升级不总结、反方给实据、直引留一句给人性、数据挂锚点、引语落情怀等
- **长难句**：全文包含 2–4 个长难句，分布在至少两个段落，类型至少两种（定语从句/状语从句/名词性从句/非谓语动词/并列复合句/强调句/倒装句等）
- **生词中文注释（此阶段只做清单，不写入正文）**：识别全文超纲词，确定带中文注释的超纲词数量 = 全文超纲词的 50%–60%（按唯一词元计；同一词族只注释首次出现的词），形式为 `comprehensive（综合的）`。**此阶段不要向正文添加任何注释**——指标检查（第 7 步 `check_passage`）必须用无注释正文，注释在导出前最后一步（第 9 步）才加入，否则注释里的括号汉字会被分词器误判为生词、拉低覆盖率。

词汇降级还要通过"地道性门槛"：目标表达必须是英语中自然、常见且语义准确的说法。与其写 `computer pictures`、`picture programs`、`light parts` 一类伪简单英语，不如保留 `computer vision`、`algorithm`、`optical parts`，再用上下文或注释减负。不要为了覆盖率牺牲搭配和专业边界。

### 6. Humanizer 受控审校

在嵌入模式下内部执行"初稿—审计—定稿"，只输出定稿。检查：

- 宣传式意义拔高和万能升华
- 无证据的 `important / promising / safer / bright future`
- 套式比喻、格言式结尾和 `The real question is`
- 为提高覆盖率而造出的不地道直译或伪简单搭配
- 连续同构短句、机械三点式和模板化转折
- 为避免重复而轮换核心术语
- 无来源的场景、感受、动作、研究或细节
- 模糊权威 `Experts say / Studies show` 是否有证据

套用行文逻辑模块时，额外过 reading-explorer-writing 的反模式清单（mental-models-heuristics.md A1–A20）。Humanizer 用于去模板化，不用于加文采。中性说明文保持中性；不要为了"像人写的"增加比喻、态度或虚构细节。

### 7. 运行指标检查

使用 `check_passage` 一步完成全部指标检查：

```
mcp__zhongkao-mcp__check_passage(text="正文", level="standard", grade=9, proper_names=["China"])
```

`grade` 固定为 9（本工具只面向九年级）。覆盖率目标区间统一（见下），`level` 必须用会话确认的档位（`standard | extended` 二选一，示例写 `"standard"` 仅为演示，不是默认值）。

`check_passage` 会自动把词数、超纲词数与 all_pass 记录到工作流状态；Part2 的 `export_docx` 会据此判断正文是否缺少中文注释并在缺注释时拦截导出。

`proper_names` 支持**单单词专名**（`"Oxford"`）和**多词短语专名**（`"rage bait"`、`"brain rot"`、`"World Health Organization"`）；短语按整体匹配，命中后短语内的每个词都不计入超纲，也不计入覆盖率分母。年度词、机构名、书名等一律列入 `proper_names`，避免被误判为超纲词。

**原文原句检测 hook（硬性，导出前必须通过）**：调用 `mcp__zhongkao-mcp__check_original_quotes(text=正文, source_text=原文)` 复核改编正文。任何一句与原文原句归一化后完全一致、或字符相似度 ≥ 95%，即返回 `all_pass=false`——该句必须改写（换结构、换措辞）后重新检测。**改编正文不得逐字引用原文任何句子**；hook 未通过不得进入第 9 步导出。

返回结果包括：
- **词汇指标**：课标词覆盖率（九年级 95%–97%）、超纲词列表及详情（按唯一词元计，同一生词反复出现只计一次）
- **篇幅指标**：正文词数、平均句长（标准档 13–15 / 拓展档 16–18）、句长 P90（标准档 ≤24 / 拓展档 ≤30）
- **专名指标**：已保留专名列表
- **年级合规**：覆盖率/超纲词比例/句长是否达标（九年级标准）
- `all_pass` 为 true 时全部通过，false 时查看具体 `status` 为 `review_required` 的项

**目标区间（九年级，覆盖率 = 1 − 超纲词比例，均按唯一词元计）：**

| 年级 | 覆盖率区间 | 超纲比例区间 |
|------|-----------|-------------|
| 9 | 95% – 97% | 3% – 5% |

覆盖率与超纲比例由同一分母（唯一词元数）互补，超纲比例不设绝对个数上限。

#### 迭代节奏

🔴 CHECKPOINT：**`check_passage` 未 `all_pass: true` 前不得进入导出**。不达标时逐项修改，每次修改后重新运行 `check_passage`，直到 `all_pass: true`。单次写作通常需要 2–3 轮迭代：

1. **第 1 轮**：聚焦覆盖率，先用 `check_text` 快速检验词汇
2. **第 2 轮**：用 `check_passage` 全指标扫描，调整平均句长和段落词数
3. **第 3 轮**：核查地道性——确保降级后的表达是自然英语，不是直译式伪简单短语

#### 段落词数检查

`check_passage` 全部通过后，逐段统计词数并汇总全文：

- **每段不超过 90 词**（软性）：优先保持语言自然流畅；超标但无更优表达可保留，但每段不超过 100 词
- **全文不超过 350 词（硬性门槛）**：正文词数（不计标题、题干、选项和中文注释）一旦超过 350，`check_passage` 的 `word_count` 将返回 `review_required`、`all_pass` 为 false，**不得交付**。必须压缩或拆分至 ≤350 词，重新运行 `check_passage` 确认 `word_count` 为 pass 且 `all_pass` 为 true 后才可进入第 8 步追溯与第 9 步导出
- 超标段压缩或拆分为两段
- 拆分后重新运行 `check_passage` 确认整体指标仍通过

### 8. 双向追溯终检

从原文到文章检查是否漏掉核心事实；从文章回到原文检查每个事实、数字、因果、概括和引述是否有来源。

任何无法回挂的内容：

- 若只是连接和指代，为其写出明确逻辑依据。
- 若是新事实、扩大范围或新评价，删除。

### 9. 导出

1. 展示**事实提取清单** + **中心思想**
2. 展示**模块匹配结果**及选择理由
3. `check_passage` 指标审校和段落词数检查结果
4. 所有详细信息（全文、指标数据、长难句清单、生词注释详情）写入**报告 Word 文档**并导出。报告 Word 用 python-docx 生成，结构约定见项目 CLAUDE.md（含任务配置、事实提取清单与中心思想、带段内标注的文章全文、模块匹配、指标报告、长难句清单、生词中文注释、写作说明、质量检查；不含"专名与引述处理"一节）。若运行环境中 python-docx 不可用，退化为在聊天展示报告内容并标注"报告 Word 未导出"。

    **报告文章全文的段内标注手法**（用 python-docx 对逐句上色）。报告内**必须含"荧光标注图例"一节**，放在"生成文章全文"节之前，逐条说明各高亮色含义：

    | 标注类型 | 高亮色 | 含义 | 判断标准 |
    |---|---|---|---|
    | 事实来源 | 黄 `WD_COLOR_INDEX.YELLOW` | 该句承载从原文提取的客观事实 | 句子含人物、时间、地点、数字、过程、结果、因果等可核验信息点；不含比喻、修饰或评价性语言 |
    | 保留原句 | 青 `WD_COLOR_INDEX.TURQUOISE` | 该句为直接引用的原文原句 | 整句逐字取自原文，未改写；其生词已纳入覆盖率计算 |
    | 长难句 | 粉 `WD_COLOR_INDEX.PINK` | 该句为长难句，并说明类型 | 句子含多层从句/非谓语/并列复合等复杂结构；类型在"长难句清单"节逐句说明 |

    注：一句可同时属于多个类别（如既是事实来源又是长难句），**正文允许对同一句叠加使用高亮**；图例中按该句最主要的属性着色即可。

    报告需**单独一节清晰列举引用的原句**（逐句列出，注明生词已纳入覆盖率计算）。报告内文章全文字体格式与 Part2 题目 Word 中的正文一致（Arial 12pt、首行缩进 0.75cm、1.5 倍行距、中文字体微软雅黑；标题 Arial 20pt 加粗居中）。质量检查只写结论（严重项/工程带宽/Humanizer/地道性/最终状态）。
5. **不导出纯文章 Word**（不再调用 `mcp__zhongkao-mcp__export_article_docx`）；文章正文由 Part2 的题目 Word（`export_docx`）承载，正文在此处带注释版本即交付给 Part2。
6. 聊天中**仅报告**"输出完成。`文章.docx` / `报告.docx`"，其中纯文章 Word 不导出、只报告报告 Word 文件名。

**简版交付**：用户明确要求简版时，跳过报告 Word，仅在聊天展示事实提取清单、中心思想、模块匹配和指标结论。

#### 导出报告 Word

**输出目录（硬性步骤）：导出前必须确认输出路径。** 若用户会话中**未明确指定**报告 Word 的保存目录，**必须先询问用户**「报告 Word 保存到哪个目录？」，待用户给出路径后再导出；不得静默默认 `<用户下载目录>/文章报告/` 或任何默认目录。用户指定的路径优先。

报告 Word 默认导出到 `<用户下载目录>/文章报告/`，目录不存在会自动创建（仅当用户未指定且确认采用默认时）。用 `run_export_report_docx`（python-docx）生成。

文档内容：报告标题（20pt 加粗居中）+ 各章节（荧光标注图例、任务配置、事实提取清单与中心思想、带段内标注的文章全文、模块匹配、指标报告、段落词数、引用原句清单、长难句清单、生词中文注释、写作说明、质量检查）。

🔴 CHECKPOINT：**交付前必须确认（逐项勾选，缺一不可），全部确认前不导出**：
- [ ] **① check_passage 已执行且 all_pass 为 true**（第 7 步硬性门槛；未达标不得进入导出）
- [ ] **② 段落词数检查已做且 word_count 为 pass**（每段 ≤90 词软性；**全文 ≤350 词硬性**，超限不得交付）
- [ ] **③ 输出目录已确认**（用户已指定，或已询问并确认采用默认目录）
- [ ] **④ 双向追溯已终检**（第 8 步：事实/数字/因果/引述均有来源）
- [ ] ⑤ 正文无任何 markdown 标记、分析标签或中文拼音注释残留
- [ ] **⑥ 正文中的生词中文注释已按第 5 步规则加入，且加在词族首次出现的词上**
- [ ] ⑦ 指标全部通过或已标注"需复核"并有理由（word_count 除外，350 硬性）

> 易错点：`check_passage` 指标检查用的是**无注释正文**；交付给 Part2 题目 Word、写入报告 Word 的正文**必须传带注释的正文**，不能把检查版原样导出。详见项目 CLAUDE.md 第 3 节「中文注释最后一步加入」。
>
> 若 Part2 的 `export_docx` 被拦截（提示"正文未包含中文注释（检出 N 个超纲词）"），说明传的正文是无注释检查版——回到本步，按第 5 步规则补中文注释（数量 = 超纲词唯一词元的 50%–60%，加在词族首次出现的词上），重新交付带注释正文。这是门禁兜底，不能靠绕过拦截代替补注释。

## 交付门槛

以下任一严重项不通过，不得把结果标为"可交付"（硬失败，需修改后重跑指标再交付）：

- 事实、数字、范围、确定性或证据类型失真
- 核心因果、转折、比较或时间线改变
- 词表外词无保留理由且不可推断或注释
- 直接引语并非原文逐字
- 新增宣传式结论、虚构细节或研究共识
- 客观事实无遗漏
- 模块匹配有理据
- 专名全部保留
- 每段功能唯一
- 2–4 个长难句，≥2 段，≥2 种类型
- 带中文注释的超纲词 = 超纲词总数的 50%–60%（同一词族只注释首次出现的词）
- **全文词数 ≤ 350（硬性）**：`check_passage` 的 `word_count` 必须为 pass；超过 350 词属硬失败，不得交付
- 报告 Word 成功导出（纯文章 Word 不导出）

**指标数值类（覆盖率、平均句长、P90）超带宽时标为"需复核"**，说明理由；不要自动宣判失败，也不要为达标损害事实。**全文词数（word_count）例外：350 为硬性上限，超限即硬失败**，不适用"需复核"。指标以第 7 步 `check_passage` 返回的 metrics 为唯一数值源，交付前逐项比对。专名不设带宽，不列入"需复核"判定。

## 常见错误（不要这样做）

| 不要做 | 后果 | 应该 |
|---|---|---|
| 遇到姓名和机构就删除 | 事实链条断裂，专名处理失准，违反「事实无遗漏」交付门槛 | 先判断信息功能，再决定保留或泛化 |
| 为了词表覆盖率写伪简单英语 | 搭配与专业边界失真，地道性门槛不过，Humanizer 也救不回 | 保留自然术语并用语境、上位词或注释支持 |
| 把单一发言写成 `Experts say` | 证据类型失真，属交付门槛硬失败 | 保持人物数量与证据类型 |
| 为了顺滑补写因果 | 新增原文没有的因果，双向追溯时无来源、只能删除 | 只显化原文可证明的关系 |
| 结尾加励志比喻 | 宣传式意义拔高，违反 Humanizer「去模板化」原则 | 结束在原文已有的结果、限制或现实意义 |
| 指标表与 JSON 数字不一致 | 破坏「指标以 check_passage 为唯一数值源」，误判达标 | 以 MCP 工具返回的 metrics 为唯一数值源，交付前逐项比对 |
| 误用无注释正文交付 Part2 题目 Word / 写入报告 Word | 中文注释缺失，Part2 `export_docx` 门禁直接拦截导出 | 指标检查用无注释正文；交付前最后一步按第 5 步规则补注释，再传带注释正文给 `export_docx` 并写入报告 Word |
